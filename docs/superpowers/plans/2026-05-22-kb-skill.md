# KB Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create `vault/persona/.claude/skills/kb-impl/SKILL.md` — a Claude skill file that implements `/kb put`, `/kb query`, and `/kb lint` for an Obsidian vault holding VEX IQ 2026 and family-member notes.

**Architecture:** A single Markdown skill file containing natural-language instructions Claude follows when `/kb` is invoked. No TypeScript, no database. `query` uses `rg` (ripgrep) for full-text search; `lint` uses `find` + file reads; `put` uses the Write tool. The vault is at the path in `VAULT_PATH` env var (always `/vault` in Docker).

**Tech Stack:** Bash (rg, find), Claude Code tools (Read, Write, Bash), Markdown frontmatter.

````markdown
## When invoked

The user (or another skill) calls `/kb <op> <args>`. Read the matching section below and execute it step by step. Do not skip steps.

---

## `/kb put <file> [--to <path>] [--summary <article>]`

Store a file in the knowledge base.

### Steps

**1. Determine target path**

- If `--to <path>` is given → target is that path (relative to vault root, e.g. `kb/vex/robot-design.md`).
- Otherwise → infer from the file's content and name:
  - If the content or filename contains any of these VEX keywords: `vex`, `robot`, `field`, `match`, `season`, `competition`, `driver`, `programmer`, `builder`, `coach` → target `kb/vex/<filename>.md`
  - If the content or filename contains member/family keywords: `member`, `family`, or any name from `$VAULT_PATH/persona/members/*.md` → target `kb/members/<filename>.md`
  - If ambiguous → target `raw/<filename>` and reply: "Placed in `raw/<filename>` — couldn't determine topic (VEX or members). Move to `kb/vex/` or `kb/members/` when ready."

**2. Check for existing file**

Run:
```bash
test -f "$VAULT_PATH/<target-path>" && echo "EXISTS" || echo "NEW"
```

If `EXISTS` → reply: "File already exists at `<target-path>`. Overwrite? (yes/no)" and wait for the user's reply before continuing. If they say no, stop.

**3. Ensure frontmatter**

Read the file content. Check if it starts with `---`.

- If frontmatter block is present, check for `tags:` and `updated:`:
  - `tags` missing or empty → add it. Use `[vex]` for `kb/vex/` targets, `[members]` for `kb/members/`. Add kebab-word stems from the filename as additional tags (e.g. `robot-design.md` → add tag `robot-design`).
  - `updated` missing → add `updated: <today-YYYY-MM-DD>`.
- If no frontmatter block → prepend one:

```
---
tags: [<folder-tag>]
updated: <today-YYYY-MM-DD>
---
```

**4. Write the file**

Use the Write tool to write the (possibly modified) content to `$VAULT_PATH/<target-path>`. Create parent directories first if needed:

```bash
mkdir -p "$(dirname "$VAULT_PATH/<target-path>")"
```

**5. Reply**

Reply with: "Saved to `<target-path>`"

---

### `--summary <article>` flag

When present, `<file>` is a binary attachment (PDF, image, etc.) and `<article>` is the path to an existing summary note. Copy `<file>` to the `assets/` subfolder next to the article:

```bash
mkdir -p "$VAULT_PATH/$(dirname <article>)/assets"
cp "<file>" "$VAULT_PATH/$(dirname <article>)/assets/"
```

Reply: "Copied `<file>` to `$(dirname <article>)/assets/`"

## `/kb query "<question>"`

Search the knowledge base and answer the question.

### Steps

**1. Extract keywords**

Pull 2–4 key terms from the question. Strip Chinese stop words (的, 是, 了, 在, 和, 有, 这, 个, 为, 以, 上, 也, 而, 但, 就, 都, 又, 才, 被, 让) and English stop words (the, a, an, is, are, was, were, how, what, when, where, who, which, that, this, it, of, to, for, in, on, at, by).

Examples:
- "这个模块怎么工作" → `模块`, `工作`
- "最近的工作笔记" → `工作`, `笔记` (recency flag = true)
- "赛程安排" → `赛程`, `安排`
- "robot design details" → `robot`, `design`

**2. Detect recency**

If question contains any of `最近`, `recent`, `latest`, `新`, `last` → set recency flag = true.

**3. Search with ripgrep**

For each keyword, run:
```bash
rg -il "<keyword>" "$VAULT_PATH/kb/"
```

Collect all file paths returned. Take the union across all keywords (deduplicate paths). If no files match any keyword → go to step 6.

**4. Rank results**

For each matched file, count how many distinct keywords it matched (by checking if each `rg` run returned it).

- If recency flag = true: read the `updated:` value from each file's frontmatter (grep for `^updated:`). Sort files by date descending; use keyword-match count as tiebreaker.
- Otherwise: sort by keyword-match count descending.

**5. Read and answer**

Use the Read tool to load the top 5 files in full.

Synthesize a direct answer from the content. Append at the end:
```
Sources: `<path1>`, `<path2>`, ...
```

**6. No hits**

Reply: "KB 里没找到相关内容。"

Do not fabricate content that isn't in the files.

## `/kb lint`

Check all notes in `kb/` for issues. Read-only — report only, no auto-fix.

### Steps

**1. Find all markdown files**

```bash
find "$VAULT_PATH/kb" -name "*.md" | sort
```

**2. For each file, run all checks**

Read the file content with the Read tool, then check:

**Check 1 — Missing frontmatter block**
Does the file content start with `---`? If not → issue: `✗ missing frontmatter`

**Check 2 — Missing required fields** (only if frontmatter exists)
Parse lines between the first `---` and closing `---`.
- Is `tags:` present and non-empty (not `tags: []` or `tags:`)? If not → issue: `✗ missing: tags`
- Is `updated:` present and non-empty? If not → issue: `✗ missing: updated`

**Check 3 — Empty body** (only if frontmatter exists)
Is there any non-whitespace content after the closing `---`? If not → issue: `✗ empty body`

**Check 4 — Broken wikilinks**
Find all `[[Target]]` patterns in the file body. For each `Target`:
- Check if `$VAULT_PATH/kb/Target.md` exists, OR
- Check if `$VAULT_PATH/kb/Target/Target.md` exists (folder note pattern)

If neither exists → issue: `✗ broken link: [[Target]]`

**Check 5 — Stale + unreferenced (STALE_DAYS = 90)**
- Parse `updated:` date (format `YYYY-MM-DD`). Compute days since that date.
- If days > 90 (stale):
  - Run: `rg -l "\[\[<stem>\]\]" "$VAULT_PATH/kb/"` where `<stem>` is the file's basename without `.md`.
  - If no other files reference it (0 results) → issue: `⚠ stale: last updated <date> (<N> days ago), no inbound links → archive candidate`

**3. Build output**

For each file that has at least one issue, print:
```
<vault-relative-path>
  <issue-line-1>
  <issue-line-2>
  ...
```

(Blank line between files.)

If no files have any issues → print: `✓ all clean`

End with a summary line:
- Issues found: `N files with issues (M archive candidates).`
- No issues: `All N files clean.`
````
