# KB Implementation Design

**Date:** 2026-05-22
**Context:** Implement the `/kb` skill for the personal assistant vault. The skill lives at `<vault>/persona/.claude/skills/kb-impl/SKILL.md` and handles knowledge base operations for a VEX IQ 2026 competition team + family members.

---

## Goals

1. Store and retrieve Obsidian-style Markdown notes
2. Tag + full-text search via ripgrep
3. Lint for missing frontmatter, broken links, and stale unreferenced notes

---

## 1. Directory Structure

```
vault/
├── kb/
│   ├── vex/          # VEX IQ 2026 competition notes
│   └── members/      # Per-member family info
├── raw/              # Unclassified inbox; run /kb ingest to classify
└── persona/          # Assistant config (unchanged)
```

`raw/` is a drop zone. Files placed there are not searchable by `query` until moved to `kb/`.

---

## 2. File Format

Every note in `kb/` must have:

```yaml
---
tags: [vex, robot-design]
updated: 2026-05-22
status: active        # optional; active | paused | done for time-bound notes
---
# Note Title

Body content...

## Sources
- [[related-file]]

## Related
- [[another-note]]
```

**Required frontmatter:** `tags` (non-empty list), `updated` (ISO date `YYYY-MM-DD`).

**Naming:** kebab-case lowercase `.md`. Non-Latin characters allowed (e.g., `赛程-2026.md`).

**Attachments:** Use folder-note pattern when a note has attachments:
```
kb/vex/robot-design/
├── robot-design.md     # folder note (same name as folder)
└── assets/
    └── cad-sketch.pdf
```

## 3. Operations

### 3.1 `put`

**Invocation:** `/kb put <file> [--to <path>] [--summary <article>]`

**Logic:**

1. If `--to <path>` is specified → write to that exact path (relative to vault root).
2. Otherwise → infer target directory from file content and name:
   - VEX keywords or tags (`vex`, `robot`, `field`, `match`, `season`, etc.) → `kb/vex/`
   - Member/family keywords or tags (`member`, family name) → `kb/members/`
   - Ambiguous → place in `raw/` and tell the user which file and why.
3. Ensure frontmatter: if `tags` or `updated` are missing, add them before writing (`updated` = today, `tags` = derived from target folder name + any obvious topic keywords in the filename, e.g. placing in `vex/` → tag `vex` is always included).
4. Dedup: if target path already exists, ask the user to confirm overwrite before proceeding.
5. Return the full vault-relative path of the written file.

`--summary <article>`: associates a binary attachment with an existing summary note. Low priority — document the flag but implement as a simple copy to the article's `assets/` folder.

---

### 3.2 `query`

**Invocation:** `/kb query "<natural language question>"`

**Logic:**

1. **Extract keywords** from the question (strip stop words; support Chinese and English).
2. **Search:** `rg -il "<keyword>" <vault>/kb/` for each keyword; take the union of all result sets. If all keywords return zero hits, proceed to step 6 (no hits).
3. **Rank:**
   - If question contains recency signal ("最近", "recent", "latest", "新") → sort by `updated:` frontmatter descending.
   - Otherwise → sort by number of distinct keywords matched per file (descending).
4. **Read:** load the top 5 matching files in full.
5. **Answer:** synthesize a direct response from the loaded content; cite source paths at the end.
6. **No hits:** reply "KB 里没找到相关内容" — do not fabricate.

---

### 3.3 `lint`

**Invocation:** `/kb lint`

**Checks (in order):**

| # | Check | Condition |
|---|---|---|
| 1 | Missing frontmatter | No `---` block found |
| 2 | Missing required fields | `tags` absent/empty or `updated` absent/empty |
| 3 | Broken wikilinks | `[[Target]]` where `Target.md` (or `Target/Target.md`) not found anywhere in `kb/` |
| 4 | Empty body | Frontmatter present but no content below `---` |
| 5 | Stale + unreferenced | `updated:` > 90 days ago **and** no other note in `kb/` links to it via `[[wikilink]]` → archive candidate |

**Output format:**
```
kb/vex/old-strategy.md
  ✗ missing: updated
  ⚠ stale: last updated 2025-11-01 (203 days ago), no inbound links → archive candidate

kb/members/alex.md
  ✗ missing: tags

2 files with issues (1 archive candidate).
```

`lint` is read-only — it reports issues but does not modify files. No auto-fix.

**Stale threshold:** 90 days, defined at the top of `SKILL.md` as `STALE_DAYS = 90`. Edit directly to change.

## Out of Scope

- Vector / semantic search (tag + full-text is sufficient for current scale)
- Auto-classification of `raw/` inbox (`/kb ingest` is a future op)
- Web clipping (`/kb clip`)
- Per-member private KB sections (members share the same `kb/members/` space)
